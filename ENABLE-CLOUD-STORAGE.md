# 🚀 Enable Cloud Storage - Quick Guide

## Simple 3-Step Process to Enable Cloud Storage Support

This guide shows you how to enable cloud storage support in your PhotoViewer app.

---

## 📋 What You're Doing

You're **adding cloud storage support** while **keeping local mode working**!

**Result:**
- ✅ Set `PHOTOS_DIR=/path` → Uses local filesystem (current behavior)
- ✅ Set `PHOTOS_DIR=cloudinary` → Uses Cloudinary (for deployment)

---

## 🔧 Step 1: Update Photo Service (2 minutes)

### Option A: Automated (Recommended)

I've created a helper script. Run this:

```powershell
# Backup current file
Copy-Item server/src/services/photoService.ts server/src/services/photoService.local.backup.ts

# Replace with cloud-aware version
Copy-Item server/src/services/photoServiceCloud.ts server/src/services/photoService.ts -Force

Write-Host "✅ Photo service updated!" -ForegroundColor Green
```

### Option B: Manual

1. **Backup your current file:**
   ```powershell
   cp server/src/services/photoService.ts server/src/services/photoService.local.backup.ts
   ```

2. **Replace with cloud-aware version:**
   ```powershell
   cp server/src/services/photoServiceCloud.ts server/src/services/photoService.ts
   ```

---

---

## 🔧 Step 3: Update Server Index (1 minute)

Add this line to `server/src/index.ts` after the imports:

```typescript
// Add after other imports
import { logPhotoServiceConfig } from './services/photoService.js';
import { logStorageConfig } from './services/cloudStorage.js';

// Add in server startup (after "Server running" log)
logStorageConfig();
logPhotoServiceConfig();
```

This logs which storage mode is active when server starts.

$env:CLOUDINARY_URL="cloudinary://your-credentials"

# Start app
npm run dev
```

**Expected:**
```
📦 Storage Configuration:
   Mode: cloud
   Cloudinary: your-cloud-name

📸 Photo Service Configuration:
   Storage Mode: cloud
   ✅ Using Cloudinary for photos
   ✅ Thumbnails generated by Cloudinary
   ✅ No server-side Sharp processing
```

**Verify:**
- Photos load from Cloudinary
- Network tab shows redirects to Cloudinary URLs
- Thumbnails served by Cloudinary CDN

    ↓

```

## 💡 Pro Tips

### Keep Local Mode for Development

During development, keep using local mode:
```env
PHOTOS_DIR=D:/Photos Ai
```

Faster, no upload needed, works offline.

### Switch to Cloud for Deployment

When deploying to Railway:
```env
PHOTOS_DIR=cloudinary
CLOUDINARY_URL=cloudinary://...
```

Better performance, global CDN, unlimited bandwidth.

### Hybrid Workflow

1. Develop locally (local mode)
2. Upload photos to Cloudinary once
3. Deploy to cloud (cloud mode)
4. Keep developing locally (local mode)

Best of both worlds!
